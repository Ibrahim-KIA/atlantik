# Atlantik API behavior

The complete operation inventory is in [endpoints](endpoints.md); request schemas and error responses are in [OpenAPI](openapi.json), served at `/openapi.json`. Run `npm run docs:api` after changing routes. The API uses `/api/v1`; a future `/api/v2` can coexist. Lists currently return at most 100 rows and require cursor pagination before use at larger tenant sizes.

Every request receives a server-generated `X-Request-Id`. All errors use `{code,message,details,requestId}`. Framework and dependency messages are hidden. Invalid JSON/input returns 400, bad credentials 401, permission/lifecycle denial 403, hidden or absent resources 404, conflicts/count quotas 409, rate/monthly quotas 429, dependency failures 503.

## Authentication

Sessions are opaque bearer credentials with a fixed 24-hour lifetime. There is no silent refresh: log in again after expiry. Logout revokes one device; session management revokes selected devices; password resets/changes and email changes revoke all devices. Logout and profile access work without a tenant selection, including when an organization is suspended. Bearer credentials must be kept in secure client storage; browsers should use an application BFF with HttpOnly cookies rather than storing long-lived tokens in localStorage. The backend accepts no ambient authentication cookies, avoiding cookie-based CSRF on these endpoints.

Verification/reset tokens expire after one hour and are single use. Resend/reset requests invalidate previous tokens. Verification is required before login; suspended and deactivated users cannot authenticate or use sessions. Reset requests always return accepted. Email changes require the current password and a new verification. Invitations expire after 48 hours, bind to the verified account email, reserve a plan seat until expiry, and are consumed atomically. Existing users can belong to multiple organizations.

## Authorization and tenancy

Tenant operations require both Bearer authentication and `X-Organization-Id`. Membership is checked on every request. Cross-tenant IDs never grant access. Owners hold organization/billing/ownership/role/key/webhook permissions. Administrators manage ordinary members, teams, settings, usage and workspaces but cannot alter owners, appoint administrators, transfer ownership, delete organizations or manage billing. Regular members receive only workspace-read permission and need explicit workspace or team membership.

Custom roles can contain the administrator permission set or a subset. Only owners create/edit/assign them; they apply to regular members, never owners/admins. They cannot grant owner permissions. Changes take effect on the next request. Team membership grants access only through explicit team-to-workspace bindings; it never confers organization administration.

Named API keys are organization-owned credentials. Only owners issue them, with a restricted scope set, expiration and one-time secret response. Rotation immediately invalidates the old secret; revocation/expiry take effect on the next request. Keys cannot call session, billing or membership-management operations. A granted workspace read scope authorizes organization-wide reads; workspace management scopes must be granted deliberately. Removing a member revokes keys they created. Inspecting metadata never returns the secret or digest.

## Organization and subscription lifecycle

ACTIVE organizations allow normal operations. PENDING organizations await operator activation. SUSPENDED blocks all normal tenant traffic while platform metadata/status controls remain available. DELETED is a permanent soft-deletion tombstone; normal access and reactivation are blocked, while audit/data retention is preserved. Hard purge requires a separately reviewed retention procedure. Owners transfer ownership atomically to another active member, with password confirmation.

TRIAL and ACTIVE subscriptions allow quota-bound work. An expired trial becomes SUSPENDED; expired ACTIVE becomes PAST_DUE; expired PAST_DUE becomes SUSPENDED on the next scheduler pass. PAST_DUE therefore has a short operational grace of up to one scheduler interval (30 seconds). CANCELLED/SUSPENDED block resource operations but retain owner billing recovery access. Explicit provider renewal restores ACTIVE; organizational suspension is separate and is never undone by payment. Billing reads and management are exempt from API request quotas so customers can recover a capped plan.

Billing provider messages must include globally unique `id`, `organizationId`, `type`, positive monotonic `version`, and optional `plan`. Compute lowercase hex HMAC-SHA256 of `timestamp + '.' + exactBodyBytes` using `BILLING_WEBHOOK_SECRET`. Send Unix seconds in `X-Atlantik-Timestamp` and the digest in `X-Atlantik-Signature`. Messages outside five minutes fail. Accepted events return `{accepted:true}`; duplicates also include `duplicate:true`. Processing is asynchronous and stale versions have no side effects. Free/Pro are seeded; Enterprise limits must be provisioned as an explicit plan before provider assignment. Payment processing itself is an adapter boundary.

## Usage and async events

UTC calendar months define request and bandwidth periods. Storage measures retained bytes across all months (reported under the sentinel period `1970-01-01`); positive events allocate bytes and negative storage events release them. Releases cannot reduce retained bytes below zero. API quota accounting covers authorized tenant operations; failed business operations still consume an admitted request. Authentication/authorization failures are independently rate limited. Current member/workspace counts enforce seat/resource limits under organization row locks. Bandwidth is positive cumulative consumption; storage is an allocation gauge. These endpoints do not implement a file-storage service; applications must integrate trusted metering and use stable event IDs. Client job requests are quota-bound. System-required billing, notifications and webhook retries remain deliverable independent of client job quota; `jobs_completed` tracks executed work separately.

Background delivery is at least once. Worker crashes can cause an email or HTTP request to be sent again after rollback. Webhook receivers must deduplicate the stable event UUID in `X-Atlantik-Event-Id`; the payload is `{id,type,data}`. Verify `X-Atlantik-Timestamp` and the same HMAC algorithm with the endpoint-specific secret. The worker retries eight total attempts with exponential backoff capped at one hour. Disabled endpoints are skipped. Delivery history reports pending/retrying/delivered/skipped/failed, attempts and sanitized errors. An operator reviews dead letters before requeueing. Secrets are encrypted at rest and only returned during endpoint creation.

Reports are requested asynchronously and delivered as email/in-app notifications. Audit logs expose administrative action, actor, timestamp, source IP, request ID and result; they never store request bodies or credentials. Tenant logs are append only through application privileges and a database trigger. Identity and platform security events have a separate audit trail.
